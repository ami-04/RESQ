# Threat model and honest limits

**What the signed log guarantees:** after the fact, anyone with our public key can prove that the
entries are exactly what this station's key signed, in this order, with nothing removed from the
middle. It does **not** prove that what an operator typed was true, that the person was physically
there, or that the person owns the code they said.

| Threat | Effect | What we do | Residual risk |
|---|---|---|---|
| Modified JSONL entry (no rehash) | content ≠ hash | `E_HASH` locally and on server | none |
| Modified entry with recomputed hash | hash OK, signature wrong | `E_SIGNATUR` (+ `E_KETTE` on successor) | none without the private key |
| Deleted entry | gap | `E_LUECKE`, `E_KETTE` | none |
| Inserted / invented entry | duplicate seq or broken chain/sig | `E_KONFLIKT` / `E_SIGNATUR` / `E_KETTE` | none without the key |
| Duplicated entry | same seq, same hash | `I_DUPLIKAT`, ignored | none |
| End cut off | no closing handover | `W_ENDE` | **If we uploaded several times**, a copy truncated exactly at an earlier handover looks complete. Mitigation: one final upload at the end of the round; earlier uploads only as backup. |
| Missing final handover | server cannot exclude missing entries | upload always writes/reuses a handover first | none |
| Stolen private key | attacker can sign a fake chain | key file outside git, `0600`, never sent; refused if equal to public test key | laptop theft = key theft (no disk encryption enforced by us). Report to organisers → replacement station. |
| Key regenerated by accident | genesis no longer matches registered key | `KeyStore` refuses to overwrite; `key-generate` blocked in live mode; readiness "Genesis uses this key" | — |
| Wrong device clock | times shifted, `W_UHR` ≥ 2 min | station time zone fixed (Europe/Berlin); Sync tab shows offset vs `server_time`; server corrects | if the clock is wrong *and* we never go online before the round, times are off until the server corrects them |
| Replayed credentials (code told to a friend) | friend checks in with someone else's code | double check-in rejected while the owner is on site | **codes are bearer secrets**: if the owner isn't there, the station cannot tell. Operator can ask for the role card. |
| Forwarded phone screenshot | remote check-in | live 4-char challenge, rotates every 30 s, valid 90 s, one-time per code → `remote_suspected` | a live call relaying the challenge defeats it; the challenge proves "someone saw the screen recently", not identity |
| Static QR code | trivially forwardable | **we do not use a static QR as proof** | — |
| Local DB corruption / power loss | torn line | fsync before success; torn last line quarantined to `log.jsonl.torn-*`; corrupted middle lines block writing (never silently repaired) | disk failure → backups (`manage.py backup`) |
| Two app instances | conflicting seqs | OS-level exclusive lock on the data dir | — |
| Dishonest / mistaken operator | wrong person, wrong role | everything is signed + attributed to the station; rejections are decided by rules, not by a reason dropdown | a malicious operator with the key can log anything. Signing gives **integrity, not truth**. |
| LAN users when `/phone` is served | access to operator API | operator API answers only to the station laptop (loopback) | anyone on the station Wi-Fi can load the static `/phone` page (harmless; it sends nothing) |
| Privacy | names in log | names only with explicit consent (versioned); none on `no_consent`; no photos/signatures; token/key never logged | the log is plaintext on the laptop |

## Offline identity assurance
Offline, the only identity factor is the code (something you know). The role card and the operator's eyes
are the physical check. We don't pretend otherwise.
